# BharatAI Education — Offline Android MVP (native Kotlin)

This is the **next, separate product milestone** after the EdgeXpert browser prototype.
This project does NOT overwrite `/home/vicky4887/myapp` or any GGUF, training data, or Python files.

## What is already implemented

- Native Android app in Kotlin / Jetpack Compose.
- Six **on-device, deterministic** calculation families: simple series/parallel circuits, uniform-motion equations, right-triangle geometry, reaction enthalpy, simple Mendelian probabilities, plane-mirror reflection.
- Typed question input and narrow, fail-closed rules extraction of values.
- Correctable structured fields and an explicit user confirmation step.
- Camera photo capture using the installed camera application, or gallery image selection.
- **Bundled** ML Kit English/Latin printed-text recognition, with no model download after APK installation.
- No `android.permission.INTERNET` in manifest; calculations/OCR never call the EdgeXpert.
- Plain steps and visible physical assumptions.
- 25 locally executed Kotlin smoke checks, plus Android/JUnit source tests.

## IMPORTANT LIMITATIONS

- **V6 GGUF is NOT embedded or run on the Android device by this MVP.** The app is intentionally offline and does not call EdgeXpert. Android llama.cpp integration is a separate next phase.
- OCR recognizes printed text, not image semantics: **it cannot understand circuit connections, graph points, or diagram lines**. Text extracted from an image may be inaccurate. Confirm every value and unit.
- The six calculators support constrained problem families, not the JEE/NEET syllabus.
- Arithmetic is verified from **user-confirmed** values, not the image/question itself. An incorrect entered value produces an incorrect answer.
- Build not completed in this environment (Android SDK/Gradle network dependencies unavailable here). The source-only ZIP is intended for opening/building in Android Studio.
- App should work offline after APK installation; compiling the APK and fetching dependencies requires a normal online development environment.

## Build on MSI EdgeXpert (DGX OS) with Android SDK

1. Extract `BharatAI_Android_Offline_MVP.zip` to `/home/vicky4887/myapp/` (a new folder is created).
2. Install or use Android Studio, Android SDK Platform **35**, Android SDK Build-Tools, and **JDK 17** (JDK 21 is also accepted by our build helper). Gradle 8.7 is NOT compatible with Java 22 as its runtime.

   **Do not run `./gradlew` directly with a Java 8 or Java 22 JVM.** Use `bash build_android.sh`, which selects JDK 17/21 and overrides stale global Gradle JVM settings. To verify: `bash check_build_jdk.sh`.
3. Run the new one-command build helper (automatically bootstraps the official Gradle wrapper if needed):

   ```bash
   cd /home/vicky4887/myapp/BharatAI_Android_Offline_MVP
   bash build_android.sh
   ```

   The helper selects a compatible full JDK, downloads the Gradle 8.7 distribution if needed, verifies its pinned SHA-256 checksum, and generates the wrapper using a minimal temporary Gradle project. If Android SDK is not detected, set `ANDROID_HOME` or use Android Studio's SDK Manager.
4. Open the `BharatAI_Android_Offline_MVP` folder in Android Studio. Allow dependency sync.
5. Use **`bash build_android.sh`** to build and test. If you specifically need raw Gradle commands, first choose a suitable JDK: `source scripts/select_build_jdk.sh; bharatai_select_jdk`, then `./gradlew -Dorg.gradle.java.home="$JAVA_HOME" :app:testDebugUnitTest :app:assembleDebug`.

6. Output APK: `app/build/outputs/apk/debug/app-debug.apk`. Install with Android Studio or:

   ```bash
   adb install -r app/build/outputs/apk/debug/app-debug.apk
   ```

7. Switch the Android device to airplane mode and verify OCR and example calculations work.

## Usage

- Pick a working example or enter a new question.
- Tap **Camera** / **Gallery** for printed text OCR (Latin script only). Correct OCR errors in the editable question field.
- Tap **Interpret text**. A safe rules parser extracts supported structures. If it refuses the question, choose the family and enter the fields directly.
- Check *all* extracted numbers, units, scientific assumptions, and targets, then tick the confirmation box.
- Tap **Calculate verified answer**. The numerical result and steps are generated by portable Kotlin, not by the LLM.

## FIXED: `No matching variant ... compatible with Java 8`

This error means the Gradle daemon is selecting a Java 8 consumer for the Android Gradle plugin. The banner mentioning `Compiling and testing with Java 22` in Gradle 8.7 release notes is **not** evidence that Gradle is running on Java 22. Run `bash check_build_jdk.sh`, then `bash build_android.sh`. The helper selects Java 17/21 and sets `-Dorg.gradle.java.home` explicitly to defeat stale `~/.gradle/gradle.properties` settings. If no JDK is installed, run `sudo apt update && sudo apt install -y openjdk-17-jdk` on your development PC.
